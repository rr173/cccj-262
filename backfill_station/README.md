# 采集回补台（offline-replayable collection backfill station）

按块交接的仪器档案采集，批次有固定网闸字节额度。本系统在**完全离线、
不接真实网关**的前提下，用本地有界传输夹具重演采集过程，交付四类可信产物：

1. **可信块**：只有同时核对块身份、整块长度、SHA-256 摘要的实收块才增加
   交付覆盖，重送不重复计数；
2. **准确的缺块表**：未交付块连同其全部尝试许可与被拒次数一并列出；
3. **可核对的额度账**：已确认实付与未终止许可的封顶保留分开列报，
   任何时刻义务合计不超过批次额度，且可仅凭日志独立重演核对；
4. **可直接使用的档案文件**：清单可声明多个档案产物，已核验块按
   清单顺序原子组装发布，缺块不发、长度摘要不符不发、路径不可越界；
5. **可安全退役的档案**：档案完成使用周期后可整体退役，移除其已
   发布文件并回收不再被任何未退役档案引用的块存储；退役不改动
   额度、收据与历史交付事实，退役档案不得再次恢复。
6. **可选的共享块池**：配置到同一池的多个批次按内容（SHA-256）复用
   已通过身份、长度、摘要三核对的相同块（即使 block_id 不同），同一份
   字节只占一份物理存储；各批次仍独立记账、独立恢复，末关联撤销才释放。

## 核心不变量

```
已确认实付(confirmed_spend) + 未终止许可封顶保留(reserved_open_caps)
<= 批次额度(quota_bytes)
```

- 许可不可复用：每个许可 ID 全局唯一，重启后同名再领一律拒绝，
  不会重新启用一套封顶。
- 许可封顶必须等于清单中该块的长度；传输侧（夹具）在封顶内发送，
  坏字节与重复尝试都计入已发字节。
- **准入前置**：领取许可前先做投影，发放后义务若超过额度则拒绝，
  拒绝事件留痕且不产生任何占用。
- 提前结束（有正式终止证 + 最终收据互相印证）后，占用从封顶降为终值，
  差额立刻可给其他缺块。
- 没有最终收据/终止证的许可，即使进程重启、即使目标块已被别的许可
  拿到，仍按封顶占用，不退款。
- 钱与数据严格分账：收据永远不证明块正确；块数据永远不动钱。

## 数据流与事件溯源

所有写操作在 `fcntl` 文件锁内执行 **校验 → 追加事件 → 当场再折叠**：

- `batch_opened` 开账冻结清单
- `permit_granted` / `permit_rejected` 许可准入（带准入快照，可审计）
- `receipt_accepted` 可信收据（progress/final，累计口径、只记一次真实字节）
- `termination_cert_held` 终止证先到、final 未到：挂起且不释放预算
- `termination_cert_discarded` 挂起证与最终收据矛盾，作废并继续按封顶占用
- `termination_confirmed` 终值核实，封顶 → 终值
- `block_verified` / `block_rejected` 数据侧三核对结果
- `archives_retired` 档案退役（只登记档案状态，不动钱账与交付事实）
- `anomaly` 全部异常凭据/越界进度/身份不符等，逐条可审计

日志每行带 CRC32 与单调序号；损坏、序号断裂、JSON 非法一律硬失败，
绝不基于被篡改的账目继续运行。`replay` 子命令只读日志重建账本，
`verify` 子命令逐字段比对重放报告与实时报告。

## 终止证的离线核实

终止证是 HMAC-SHA256 签名信封 `{payload, signature}`，密钥在 `init`
时写入数据目录（0600 权限）。验签用常数时间比较。每许可至多一份：

- 同证重放 → 幂等忽略；
- 坏签名 → 异常，不能冒充终止证；
- 签名有效但终值与已核实终值冲突 → 异常，绝不覆盖；
- 终止证与最终收据终值不一致 → 拒绝减少占用，许可继续按封顶保留。

## 档案产物声明与恢复

清单可选携带 `archives`（没有该字段的旧批次完全按原方式工作）。每个
档案产物在开账冻结时声明并校验：

```json
{
  "archive_id": "ARC-INSTR-FULL",
  "path": "instrument/full_profile.dat",
  "block_ids": ["b1", "b2", "b3", "b4"],
  "length": 900,
  "sha256": "41bcc1e9..."
}
```

- `archive_id` 批次内唯一；`path` 是输出目录内的相对路径，空段、
  `.`、`..`、绝对路径、盘符、反斜杠在冻结期一律拒绝；
- `block_ids` 按**原顺序**排列，引用的块必须都在块清单内，不同档案
  （以及同一档案内）可以重复引用同一块；
- `length` 必须等于组成块长度之和，`sha256` 为 64 位十六进制整档摘要。

三核对通过的块在追加 `block_verified` 事件前，先原子落入数据目录的
`blocks/` 仓库（块身份经十六进制编码成扁平文件名），恢复时逐块重新
核对长度与摘要，仓库文件缺失或被篡改按数据目录损坏硬失败。

`restore` 操作在同一把文件锁内执行，安全保证：

1. **缺块不发**：某档案所需任一块尚未交付，整个档案跳过，不生成该
   档案的任何新文件（连临时文件都不写），结果中逐项报告缺少的块；
2. **发布前双核对**：组装完成后再核对组成文件的总长度与整档
   SHA-256，只有全部匹配清单才 `os.replace` 原子发布；
3. **读者不可见部分文件**：组装发生在输出目录内的隐藏临时文件中，
   发布是单次原子改名，任何时刻读取者要么看到旧完整文件、要么看到
   新完整文件；
4. **路径围栏**：输出目录经 `realpath` 规范化，目标路径（含父目录
   与符号链接）必须仍在输出目录之内，逃逸即致命拒绝；
5. **幂等且不动账**：恢复是纯派生操作，不追加任何日志事件，许可、
   额度、收据账完全不变；已发布且与清单逐字节一致的文件原样保留
   （权限不改），重复恢复得到一致的文件与状态。

```bash
python3 -I run.py restore --data-dir run/demo_data \
  --output-dir run/demo_archives
```

`restore` 退出码：全部档案已发布（或无档案声明）0；存在缺块被挡下
的档案 2；路径越界、块仓库损坏等致命错误 4。对账报告的 `archives`
节给出每个档案的就绪状态与缺块清单，`replay`/`verify` 同样包含该
派生视图并逐字段一致。

## 档案退役与存储回收

档案完成使用周期后，`retire` 操作把一个或多个本批次已声明的
`archive_id` 标记为退役，移除其已发布文件并回收不再被引用的块存储：

```bash
python3 -I run.py retire --data-dir run/demo_data \
  --output-dir run/demo_archives \
  --request retire_req.json     # {"archive_ids": ["ARC-INSTR-FULL", ...]}
```

- **原子校验**：请求含任何未声明的 `archive_id` 时整次拒绝——不追加
  事件、不移除文件、不回收块，状态完全不变（退出码 2）；
- **幂等**：退役状态持久化在日志里（`archives_retired` 事件），重复
  执行同一退役请求结果一致——已退役的档案不再追加事件，文件清理
  本身幂等，还能修复上次崩溃遗留的半成品清理；
- **退役不可恢复**：退役档案在恢复时逐项标记 `retired` 并跳过，换
  输出目录也一样，绝不重新发布；
- **共享块安全**：一个块可能被多个档案引用，只有不再被任何未退役
  档案引用的块才删除存储文件；仍被引用的块保留，继续支持存活档案
  的恢复。已发布文件的移除与恢复共用同一路径围栏，越界目标、目录
  占位一律致命拒绝，空父目录逐级修剪；
- **不动钱账与历史**：退役不触碰许可、额度、收据与历史可信交付事实。
  对账报告的 `delivery` 节区分三类口径：`delivered`（历史已交付，
  不随退役改变）、`retained_block_ids`（当前仍保留存储的已交付块）、
  `reclaimed_block_ids`（已交付但存储已回收的块），`retired_archives`
  列出已退役档案；`replay`/`verify` 的派生视图逐字段一致。

`retire` 退出码：成功 0；含未声明档案（整次拒绝）2；用法错误 3；
路径越界等致命错误 4。未声明档案的旧批次没有可退役对象，任何
`archive_id` 都按未声明拒绝，其余行为完全不变。

## 可选共享块池（按内容去重的跨批次存储）

多个独立采集批次可能收到内容完全相同的数据块，各自保存会让同一份字节
重复占盘。清单可**可选**携带 `shared_pool`，把本批三核对通过的块导向一个
共享池；没有该字段的批次以及所有既有数据目录完全按原方式工作，物理块
仍只落在本批 `blocks/` 仓库：

```json
{
  "batch_id": "BATCH-A",
  "quota_bytes": 1000000,
  "blocks": [ ... ],
  "archives": [ ... ],
  "shared_pool": { "path": "/var/lib/backfill/pools/main" }
}
```

- `path` 在开账冻结时规范化为绝对真实路径并随清单冻结，`pool_id` 由该
  路径确定性导出；指向同一物理目录的批次必然落到同一池，不依赖调用时
  的工作目录。配置非法（空路径、非对象、NUL 字节）在冻结期即拒绝。
- 池目录独立于任何批次，结构为：

  ```
  <pool>/
    pool.lock                 跨进程互斥锁
    pool.jsonl                池自身的仅追加日志（CRC32 + 单调序号 + fsync）
    objects/<sha256>.bin      内容寻址对象，扁平十六进制文件名
  ```

### 内容寻址与按批关联

- 三核对（块身份、整块长度、SHA-256）仍在批次侧完成；通过后块不再写入
  本批 `blocks/`，而是按内容 SHA-256 原子落入池的 `objects/`，并在池日志
  追加 `pool_linked`，登记一条 `(batch_id, block_id) → 摘要` 的关联。
- **同内容只存一份**：不同批次、或同一批次不同 `block_id` 关联到同一
  摘要时复用同一物理对象，只新增关联计数；对象在首次需要时才写盘。
- **钱账与数据各自独立**：许可、收据、额度、退役状态仍只存在各批自己的
  日志里，池不参与任何批次账本。恢复结果继续只由本批清单与本批账本
  决定：恢复时除逐块复核长度/摘要外，还要求池中存在**本批**对该块的
  有效关联——别的批次的关联不能顶替本批未交付的块。
- 批次报告新增 `shared_pool` 节，只含冻结配置与本批已交付内容摘要，
  因此 `replay`/`verify` 仍可逐字段一致核对（不触碰池文件系统）。

### 按内容查看库存

`pool-inventory` 按 SHA-256 列出每个对象：长度、是否仍占用物理存储、
以及关联它的全部批次/块身份（含各批数据目录）：

```bash
python3 -I run.py pool-inventory --pool-dir /var/lib/backfill/pools/main
# 或从任一配置了该池的批次自动定位：
python3 -I run.py pool-inventory --data-dir run/demo_pool_batches/batch_a
# --gc-check 额外只读标注疑似残留（未确认交付）的关联，不做修改
```

### 退役语义：只撤销本批关联，末关联才释放存储

- 批次内档案退役/清理后，池后端只撤销**本批**对相应已交付块的关联
  （`pool_released` 事件）；其他批次的关联与对象文件原样保留，其档案
  恢复不受任何影响。
- 一个对象在仍关联任一批次时绝不删除；只有最后一条关联撤销、对象不再
  关联任何批次后，才 unlink 物理文件并 fsync 目录。`retire` 返回的
  `pool_links_released` 逐块给出剩余关联数与本次是否真正释放了存储。
- 退役的幂等性、原子拒绝、发布文件移除、路径围栏、钱账与历史交付事实
  不变等保证与本地仓库完全一致；重复退役对已撤销关联返回 `not_linked`。

### 重启、并发与崩溃一致性

- 关联的登记/撤销都在池锁内做“校验 → 追加池事件 → 当场折叠”，池日志
  每行带 CRC 与单调序号，损坏即硬失败。已确认的关联随事件 fsync 持久化，
  进程重启或多进程并发都不会让它消失；登记与撤销均幂等。
- **锁序**：所有写路径都先取批次数据目录锁、再取池锁，全系统统一顺序，
  不存在锁环；不同批次的命令在池锁上排队，事件流保持全序。
- **崩溃对账**：每次持锁打开池都先核对日志投影与磁盘对象——磁盘上无
  关联的孤立对象（对象已写而关联事件未落，或末关联撤销后文件未删）
  自动清扫并记 `pool_reconciled`；有关联却缺失的对象属于池存储损坏，
  硬失败，绝不静默用坏状态恢复。
- **残留关联 GC**：若崩溃发生在“池关联已落、批次 `block_verified` 未
  确认”之间，`pool-gc`（或 `pool-inventory --gc-check` 预览）会逐个重读
  各批日志核实：只撤销对应批次未确认交付（或批次目录已不存在）的关联，
  已确认交付的关联绝不撤销，并随之释放失去全部关联的对象。

```bash
python3 -I run.py pool-gc --pool-dir /var/lib/backfill/pools/main
python3 -I demo/run_shared_pool_demo.py     # 跨批次去重/退役/对账完整演示
```

`pool-inventory`/`pool-gc` 退出码：成功 0；池不存在或批次未配置池等用法
错误 3；池日志/对象损坏等致命错误 4。


## 快速开始

```bash
# 1. 端到端演示（输出在 run/ 下，固定种子可重复）
python3 -I demo/run_demo.py

# 2. 全量规则测试、档案恢复/退役测试与并发压力
python3 -I tests/test_station.py
python3 -I tests/test_restore.py
python3 -I tests/test_retire.py
python3 -I tests/test_concurrency.py

# 3. 独立重演与交叉核对
python3 -I run.py replay --data-dir run/demo_data
python3 -I run.py verify --data-dir run/demo_data

# 4. 档案恢复（已核验块组装为完整文件，缺块档案返回退出码 2）
python3 -I run.py restore --data-dir run/demo_data \
  --output-dir run/demo_archives

# 5. 档案退役（标记退役、移除已发布文件、回收专属块存储）
python3 -I run.py retire --data-dir run/demo_data \
  --output-dir run/demo_archives --request retire_req.json

# 6. 共享块池：跨批次去重演示与按内容库存查看
python3 -I demo/run_shared_pool_demo.py
python3 -I run.py pool-inventory --pool-dir run/demo_shared_pool
```

CLI 退出码：成功 0；业务拒绝（准入不足/摘要不符/档案缺块/退役含未
声明档案等）2；用法错误 3；账目或块仓库损坏、恢复/退役路径越界等
致命错误 4。

## 演示场景覆盖

- 完整收到但经历乱序、重复收据流；
- 收到一半断开（终值 < 封顶），终止证先到挂起、final 后到自动确认；
- 坏字节照计费、块摘要不符被拒，二次尝试单独计费后回补成功；
- 重送同一完备块不重复计覆盖；另一许可实收相同内容仍单独计费；
- 超封顶进度、矛盾重放、未知许可、坏签名/冲突终止证全部记异常；
- 模拟进程崩溃后仅凭日志重建，无退款、无许可重新启用；
- 未终止许可长期按封顶保留，把可用额度压到新许可付不起，准入拒绝留痕；
- 最终缺块表准确列出唯一未交付块；
- 档案恢复：两个档案（含跨档案共享块）原子发布，依赖缺块 b5 的档案
  被整体挡下且不生成文件，二次恢复原样确认、日志序号不变；
- 档案退役：退役 ARC-INSTR-FULL，移除其已发布文件并回收独占块
  b2/b3 的存储；共享块 b1/b4 保留并继续支持 ARC-INSTR-B14 的恢复；
  重复退役幂等、含未知档案的请求整次拒绝、退役档案不再恢复。

## 边界与取舍

- 只使用 Python 标准库，`python3 -I` 隔离模式运行，不依赖网络与第三方包。
- 不实现多个账期之间的结转；清单允许单账期额度小于整批全长，
  超支完全由运行时准入控制拦截。
- 挂起终止证同样进日志持久化，重启后同证重交保持幂等。
- 块仓库与恢复出的档案都是清单/日志的派生产物：恢复不写日志、不动
  钱账；删掉块仓库后可由重新交付的完备块重建，账本本身不受影响。
- 退役是单向的：没有"取消退役"操作。被回收的块存储文件不会因完备
  块重送而复活（重送本就不重复落仓）；退役档案的块如需再次使用，
  只能在后续新批次中重新采集交付。
- 共享块池是可选的纯存储层：不改变任何批次的钱账语义，池目录可放在
  数据目录之外；未配置池的批次不创建任何池文件。池对象按内容 SHA-256
  寻址，天然去重但不做压缩/加密；池的可信边界与批次一致——只接受已经
  通过批次侧三核对的块，池内读取还会再次复核长度与摘要。
